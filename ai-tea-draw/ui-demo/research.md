# 茶绘画板 UI 考察与 Demo

考察日期：2026-10-05。范围为工具位置、参数调整、画布导航、图层组织以及桌面/触屏差异；不做价格、绘画质量或产品排名。事实来自下列官方手册，设计建议是针对茶绘的推断。本次没有实际操作这些产品的原生应用。Demo 内的布局示意是重新绘制的简图，不是产品截图。

## 同类产品如何布置

| 产品 | 主要布局 | 高频交互 | 对茶绘的参考价值 |
| --- | --- | --- | --- |
| Krita | 上方工具栏、中央画布、可移动/停靠的功能面板 | 笔刷参数放工具栏；右键在光标附近打开调色板；工作区可保存 | 桌面常用操作位置稳定，辅助面板可收起 |
| Procreate | 顶部绘画/编辑工具，侧边粗细与透明度滑杆 | 图层和颜色按需展开；侧栏可左右切换；触屏导航有手势 | 让非绘画手调整参数，给画布更多空间 |
| Clip Studio Paint | Simple Mode 提供精简的工具、图层和底部参数；Studio Mode 提供完整面板 | 当前工具再次点击展开选项，图层支持触屏整理 | 桌面和触屏需要不同密度，切换布局应保留作品状态 |
| Concepts | 可移动的工具轮或工具条，图层等面板可折叠 | 工具、颜色、粗细、透明度集中；工作区可适应左右手 | SVG 项目可以借鉴矢量对象直接修改与紧凑参数区 |
| Sketchbook | 顶部工具栏，按工具展开二级选项，浮动笔刷/颜色控制 | 手机默认隐藏更多面板，Double Puck 和快捷菜单减少移动距离 | 小屏重新组织操作，保持当前工具的清楚高亮 |

### Krita

官方界面说明把上方工具栏、可停靠的 Dockers、状态栏和浮动面板分开。笔刷大小与透明度属于工具栏；图层、调色板、笔刷预设属于可显示、隐藏和重排的面板。右键弹出调色板在光标附近提供常用笔刷和颜色。

对茶绘的推断：采用稳定的桌面工具位置，再允许收起辅助面板；默认只展示绘画所需功能。面板可定制不等于默认需要塞满。

来源：[Krita 官方界面与导航](https://docs.krita.org/en/user_manual/getting_started/navigation.html)。

### Procreate

官方手册将绘画工具集中在右上方，编辑工具放在左上方。侧栏提供粗细、透明度及撤销/重做，位置可左右切换和上下移动。手势包含双指缩放、双指轻点撤销和三指轻点重做；画布导航还提供单触点辅助入口。

对茶绘的推断：触屏参数应靠近非绘画手，并提供左右手布局；手势应有可见按钮作为替代。其位图笔刷、涂抹和压感不能靠 SVG UI 改版自动获得。

来源：[Procreate 官方界面](https://help.procreate.com/procreate/handbook/interface-gestures/interface)、[官方手势](https://help.procreate.com/procreate/handbook/interface-gestures/gestures)。

### Clip Studio Paint

官方平板布局区分 Simple Mode 与 Studio Mode。Simple Mode 保留左侧工具与颜色、右侧图层、底部粗细和透明度滑杆；Studio Mode 提供可定制的完整功能面板。Simple Mode 中，再点当前画笔可以打开笔刷列表，点回画布后列表关闭。

对茶绘的推断：相同作品状态可以配合不同屏幕布局。游戏任务应改变必要操作的显示，而不是让绘画工具和整场房间管理始终竞争空间。

来源：[官方平板界面](https://help.clip-studio.com/en-us/manual_en/090_tablet/Tablet_interface.htm)、[Simple Mode 操作](https://help.clip-studio.com/en-us/manual_en/090_tablet/Using_Simple_Mode.htm)。

### Concepts

官方手册描述工具轮中的常用工具、内部参数和中心颜色，以及工具轮/工具条切换。图层、精确工具和对象库可以移动；工作区有普通、紧凑、隐藏状态，并提供左右手调整方式。

对茶绘的推断：颜色、粗细、透明度放在工具附近；选择后的矢量对象提供直接修改。轮盘需要额外学习，第一版 Demo 采用可见工具条，再评估轮盘需求。

来源：[Concepts 官方工作区](https://concepts.app/en/manual/workspace)。

### Sketchbook

官方说明区分桌面、平板和手机。顶部工具栏选择当前工具，部分工具会展开二级工具栏；桌面工具栏可移动或隐藏。移动端有 Double Puck、快捷菜单及按需出现的面板，手机因空间有限而隐藏更多编辑器。

对茶绘的推断：手机布局应独立组织，常用入口继续可见；隐藏面板和手势应减少操作距离，并保留明确入口。

来源：[Sketchbook 官方基础界面](https://help.sketchbook.com/docs/basic-ui-elements)、[官方各端工具栏](https://help.sketchbook.com/docs/toolbars)。

## 针对当前茶绘的设计决定

1. **先给一张可画的草稿。** 进入即可选择画笔。新建草稿是文件管理操作，不再是开始画画的前置步骤。
2. **桌面位置稳定。** 左侧是直接可见的工具，顶部是当前工具参数，右侧默认图层。房间、伙伴、Agent 在辅助面板切换。
3. **触屏重新布局。** 平板保持侧边工具、底部参数，图层按需打开；手机把工具移到底部，面板变成底部抽屉。提供左右侧工具切换。
4. **改完直接生效。** 颜色、粗细和透明度统一直接修改。选择对象后提供拖动、角点缩放、旋转柄、复制和删除。
5. **草稿和全场在同一画布位置切换。** 明确标注私有草稿与只读的全场画布。游戏模式中未揭晓的全场入口受到限制。
6. **发布是独立且清楚的动作。** 提交时显示作品预览和名称；演示队列有待审状态，模拟批准后才出现共享结果。
7. **把系统细节放到需要时。** 主绘画区不展示序号、SVG 路径 d、工具协议或上下文 JSON。

## 本次 Demo 的实际范围

- 可实际操作：画笔、对象橡皮、矩形、椭圆、直线、选择拖动、缩放/旋转对象、颜色/粗细/透明度调整、撤销重做、图层新建/改名/排序/显示/锁定、画布缩放和平移、SVG 导出。
- 触屏：工具栏与参数区重排，临时面板、左右侧工具、双指缩放/平移、双指轻点撤销。手机保留基础可见工具；矩形、椭圆和直线从形状按钮展开。
- 本地保存：使用浏览器 localStorage 保留演示草稿、提交快照和全场结果，存储失败会提示导出。撤销历史仅保留在当前页面。
- 流程模拟：人物、房间、玩法任务、Agent 添加气泡、提交和审核。按钮明确标注演示；Agent 使用固定 SVG，不调用模型。
- 本次不接入正在运行的 Steam 会话，不提交真实作品，不修改现有 studio 页面。两套布局共享同一份本地演示作品。
- 绘图以 SVG 对象为源。对象橡皮删除整个对象；没有位图擦除、纹理笔刷、完整压感曲线、完整钢笔编辑或实际多人同步。

## 后续正式接入时的约束

UI 草稿与正式 drawing.open / drawing.patch 的版本、操作序号需要由适配层管理。交互预览在本地即时显示，完成操作后再按当前协议提交；遇版本冲突须重新读取状态。不能用取消 550 ms 写入间隔的方式规避服务限流。

公共画布继续只显示权限允许的已发布结果。游戏任务沿用现有 taskId / phaseId 等绑定；审核入口沿用房主权限，绘图 Agent 不获得管理凭据。Demo 的本地模拟不能作为真实 Steam、多账号联机或游戏权限验证证据。

## 启动与验证

在 ai-tea-draw 目录执行 npm run ui:demo，默认 URL 为 http://127.0.0.1:5890/；布局切换会更新 layout 查询参数，无需访问 token。

执行 npm run verify:ui-demo 进行无头浏览器验证。验证范围为实际绘图、编辑、保存、导出、提交演示、考察入口，以及桌面、平板、手机窄屏布局。结果和截图写入 verification/ui-demo/。

2026-10-05 验证结果：17 项功能检查通过，浏览器运行错误为 0。检查了 1440 × 960、1100 × 800 桌面，1024 × 768 平板，390 × 844 和 320 × 700 手机尺寸；常用工具无重叠或横向溢出。手机工具点击区域至少为 44 × 44 像素。双指缩放/平移未生成误画笔画，双指轻点撤销通过浏览器触控事件验证。以上为无头浏览器验证，未做实体触屏笔、压感或手掌误触的硬件验证。
